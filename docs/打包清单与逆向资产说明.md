# 打包清单与逆向资产说明（本地参考，禁止封装进软件）

> 本文件仅用于自己维护项目时参考，**不要随 exe 封装出去**。
> 打包时 PyInstaller 必须排除 `docs/` 目录（尤其本文件）。

## 一、必须封装进软件的内容（运行时真正需要）

### 1. 入口与核心代码

- `app.py` —— 客户端主程序入口（卡密激活 + 主界面）
- `admin_app.py` —— 卡密管理端（可选：单独打包，不进用户客户端）
- `updater.py` → 打包成 `updater.exe`，**内嵌进用户端 exe**（不单独分发），用于热更新时替换旧程序
- `scripts/` 中以下运行时模块：
  - `bydsj_client.py` —— 大世界登录、token、背包协议
  - `gaia_login.py` —— 通行证登录、快速鉴权、改密
  - `query_service.py` —— 账号类型自动判断
  - `security_center.py` —— 会话、信任设备、安全中心
  - `warehouse.py` —— 仓库查询与存取
  - `card_auth.py` —— 卡密激活客户端
  - `local_store.py` —— 本地加密账号库
  - `device_info.py` —— 设备码读取/缓存（可选，代码里已按需引入）
  - `password_utils.py` —— 批量改密密码生成
  - `account_import.py` —— 粘贴解析/去重/TSV
  - `proxy_pool.py` —— 动态代理池

### 2. 数据模板（协议必须，漏了会登录失败）

- `data/flow5_template.bin` —— 大世界换 token 模板
- `data/tokenlogin_template.bin` —— 通行证换游戏会话模板

### 3. 资源文件

- `assets/items/*.png` —— 17 个道具图标文件（界面当前展示 16 项，钻石图标保留备用）
- `assets/app_icon.ico` —— 用户端 exe 图标（由 `图标.png` 转换，仅打包时使用，可不进运行时数据）

### 4. 第三方依赖（打进 exe，无需目标电脑装 Python）

- PySide6
- cryptography
- httpx
- pyDes
- （打包器：用户端 Nuitka；updater/管理端 PyInstaller）

## 二、不需要封装的内容（保留在本机，后续更新可能用）

### 1. 逆向/寻址资产（体积大，必须排除）

- `dumps/` —— 内存转储、抓包文件、协议模板备份
- `tools/il2cpp/` —— 反编译产物（含 Python2 旧脚本，禁止整目录打包）
- `tools/frida/` —— Frida 相关工具

### 2. 开发期脚本（运行时用不到）

- `scripts/read_proc.py`、`scripts/disasm.py`、`scripts/read_inventory.py`
- `scripts/gaia_cipher.py` —— 白盒解密工具（密钥已固化进 `gaia_login.py`）
- `scripts/keep_dnat_loop.sh`、`scripts/start_keep.sh`
- `tools/normalize_item_icons.py` —— 图标配准工具（换图时重新生成 `assets/items/`，保留本地）
- `packaging/` —— 打包脚本/spec（Nuitka + PyInstaller，保留本地，不进 exe）

### 3. 服务器与管理相关（单独部署，不进客户端 exe）

- `server/` 整个目录（FastAPI 卡密服务器，部署到云服务器）
- `tests/` 测试代码
- `docs/` 全部文档（含本文件）

### 4. 本地运行缓存/环境

- `.venv/` 虚拟环境
- `data/device_code.txt` —— 本机设备码缓存（每台电脑各自生成，不进包）
- `%APPDATA%/BydsjManager/` —— 账号库、日志、代理配置（运行时自动生成）
- `server/data/cards.db` —— 卡密数据库（只留在服务器/本机，绝不外发）

## 三、打包时的硬性要求

1. 用户端 Nuitka 打包必须包含：
   - `data/flow5_template.bin`
   - `data/tokenlogin_template.bin`
   - `assets/`（items 图标 + app_icon.ico）
   - `updater.exe`（作为数据文件内嵌进用户端 exe）
2. 打包必须排除：
   - `dumps/`、`tools/`、`tests/`、`docs/`、`packaging/`、`server/`、`.venv/`
3. 不要打包任何账号密码、卡密、`cards.db`、代理 authkey。
4. 服务器 `/data/releases/`（热更新文件与版本清单）需随数据库一起备份。
5. 打包后在一台干净电脑（无 Python、无本项目）上验证：
   - 卡密激活
   - 大世界/通行证两种登录
   - 刷新背包/仓库
   - 仓库存取
   - 批量刷新（含代理）
   - 日志写入与打开日志目录

## 四、后续更新软件时可能还要用到哪些本机资产

- `dumps/20260810/protocol/` —— 新协议字段变化时重新分析
- `data/*.bin` —— 游戏版本更新后可能需要重新抓模板并替换
- `scripts/gaia_cipher.py` —— 通行证 SDK 配置变化时重新解
- `tools/il2cpp/` —— 游戏客户端升级后重新反编译对照

**结论**：封装只带走“运行时代码 + 协议模板 + 图标 + 依赖”；逆向资产和文档全部留在本地，避免 exe 臃肿，也方便后续更新维护。
